## 2. Frontend

**Framework:** React 18 + TypeScript + Vite 6  
**Package manager:** npm (pnpm not installed on this machine)  
**Entry point:** `src/main.tsx` → `src/app/App.tsx`  

**package.json scripts:**
```json
"dev":   "vite"
"build": "vite build"
```

**Key dependencies:** recharts 2.15, lucide-react 0.487, radix-ui (full suite), tailwindcss 4, react-router 7

**App.tsx — all UI in one file (~970 lines):**

| Screen | Nav ID | Data keys consumed |
|---|---|---|
| Overview | `overview` | `kpis`, `priceByCat`, `discByCat`, `discByBrand`, `top20` |
| Cross-Platform | `crossplatform` | `matchedPairs`, `catCheaper`, `platComp` |
| Statistics | `statistics` | `scatterData`, `cvData`, `outliers`, `pearsonR` |
| Sentiment | `sentiment` | `sentDonut`, `sentTable` |
| Catalogue | `catalogue` | `products`, `brandPanel`, `sentTable` (for ratingByCat) |
| Pipeline Health | `pipeline` | `platformSummary`, `pipelineLogs` |
| Settings | `settings` | static only |

**Data loading:** `useEffect` on mount fetches `/frontend_data.json`. Shows loading spinner while pending, error screen if fetch fails (with `allow_nan=False` guarantee on the Python side).

## 3. Backend

**Language:** Python 3.x  
**Core dependencies:** `requests`, `beautifulsoup4`, `lxml`, `pandas`, `rapidfuzz`, `apscheduler`, `streamlit` (unused), `plotly` (unused)

| Module | File | What it does |
|---|---|---|
| Scraper | `src/scrapers/amazon_scraper.py` | HTTP scrape Amazon.in search results, writes JSON to `data/raw/` |
| Scraper | `src/scrapers/flipkart_scraper.py` | Same for Flipkart |
| ETL | `src/etl/run_etl.py` | Orchestrates: load_raw → validate → clean → dedup → normalize → load_to_db → log |
| ETL | `src/etl/load_to_db.py` | Inserts into `products` + `price_history` + `reviews` (one price_history row per product at load time) |
| Matching | `src/matching/fuzzy_match.py` | RapidFuzz token_sort_ratio against all Amazon×Flipkart product pairs per category |
| Matching | `src/matching/run_matching.py` | CLI entry point; saves matches to `product_matches` table and `data/match_results.csv` |
| Analytics | `src/analytics/analytics.py` | 7 functions over SQLite; returns `dict[str, DataFrame]` |
| Analytics | `src/analytics/run_analytics.py` | Runs all 7, saves 16 CSVs to `data/analytics/` |
| Export | `export_data.py` | Reads DB + CSVs, maps to App.tsx data shapes, writes `frontend_data.json`, auto-copies to `public/` |

## 4. Database

**Location:** `data/price_comparison.db` (478 products loaded as of last ETL run)  
**Second DB:** `database/marketpulse.db` — created by `src/create_db.py` but **never written to**; ignore it.

**Schema (`sql/schema.sql`):**

```sql
products        (product_id PK, source, product_name, brand, category,
                 current_price, currency, product_url, last_updated)

price_history   (history_id PK, product_id FK, price, recorded_at)
-- NOTE: only ONE row per product is inserted (at ETL load time)
-- This means discount_analytics always returns 0 rows

reviews         (review_id PK, product_id FK, rating, review_count, sentiment_score)
-- sentiment_score is always NULL (not computed)

product_matches (match_id PK, amazon_product_id FK, flipkart_product_id FK, confidence_score)
-- 4 pairs currently: 3 smartphones + 1 moisturizer

etl_run_log     (run_id PK, source, records_processed, status,
                 duplicates_removed, missing_values_fixed, invalid_rows_removed, run_timestamp)
-- 1 log entry currently
```

**Categories in DB:** headphones, kitchen_tools, laptops, moisturizer, smart_tv, smartphones  
(Not the mock categories: Electronics, Clothing, Sports, etc. — those were placeholder data)

## 5. Data Flow

```
src/scrapers/run_all_scrapers.py
    ↓ writes JSON to data/raw/
src/etl/run_etl.py
    ↓ validates, cleans, deduplicates, normalizes
    ↓ inserts into data/price_comparison.db  (products + price_history + reviews)
src/matching/run_matching.py
    ↓ reads products table, runs RapidFuzz
    ↓ inserts into product_matches table
src/analytics/run_analytics.py
    ↓ runs 7 analytics functions against DB
    ↓ writes 16 CSVs to data/analytics/
export_data.py
    ↓ reads DB + CSVs
    ↓ maps to 17 JSON keys matching App.tsx variable shapes
    ↓ writes frontend_data.json (root) + copies to public/
Browser fetches /frontend_data.json on page load
    ↓ React state populated
    ↓ All 7 screens render with real data
```

## 6. Current State

### Working
- Full ETL pipeline: raw JSON → SQLite DB (478 products across 6 categories)
- Fuzzy matching: 4 matched pairs in `product_matches`
- All 7 analytics functions run and produce CSVs
- `export_data.py` generates valid JSON (NaN scrubbed, `allow_nan=False`)
- Frontend dev server runs at http://localhost:5173
- All 7 screens render; real data flows through for: KPIs, price by category, platform comparison, scatter chart, volatility, outliers, sentiment, products catalogue, brand panel, platform summary

### Known Gaps / Broken
| Issue | Root cause |
|---|---|
| `discByCat`, `discByBrand`, `top20` all return 0 rows | ETL inserts only 1 `price_history` row per product; discount logic requires ≥2 rows (first as MRP, last as current) |
| `pipelineLogs` shows only 1 entry | Only 1 ETL run logged so far |
| `matchedPairs` / `catCheaper` only cover 2 categories | Fuzzy matching threshold=85 is strict; only 4 pairs found across all data |
| `database/marketpulse.db` exists but is empty | `src/create_db.py` points there; ETL points to `data/price_comparison.db` — path mismatch |
| `sentiment_score` always NULL | Not computed; sentiment is proxied from star ratings only |
| Streamlit + Plotly in requirements.txt | Leftover deps; no Streamlit app exists |

## 7. Commands to Run

### Full pipeline (run in order)

```bash
# From MarketPulse-main/

# 1. Scrape (optional — raw JSON already exists)
cd src/scrapers
python run_all_scrapers.py --pages 2

# 2. ETL — load raw JSON into SQLite
cd src/etl
python run_etl.py

# 3. Fuzzy matching — populate product_matches table
cd ../..
python src/matching/run_matching.py --db data/price_comparison.db --threshold 85

# 4. Analytics — regenerate all CSVs
python src/analytics/run_analytics.py

# 5. Export — generate frontend_data.json and copy to public/
python export_data.py
```

### Frontend

```bash
cd "Professional Dark-Theme Dashboard"
npm install          # first time only
npm run dev          # dev server at http://localhost:5173
npm run build        # production build → dist/
```

### Re-export only (after new scrape/ETL, no need to restart frontend)

```bash
# From MarketPulse-main/
python export_data.py
# Then refresh browser
```
